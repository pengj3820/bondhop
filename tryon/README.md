# 固定模特 AI 换装

用户在网页里**自由组合单品**，换装时**只做图层叠加**，不调用 AI。所有服装部件都在**离线阶段**用 AI 生成，生成时直接穿在固定模特身上，所以每个部件天然和模特对齐。

- 网页换装：`web/index.html`。需要用静态服务器打开，例如在 `tryon/web` 目录下运行 `python3 -m http.server`。
- 离线生产：`pipeline/batch.py`

## 离线流水线（`pipeline/`）

| 步骤 | 脚本 | 做什么 |
|---|---|---|
| 1 | `gen_model.py` | 生成固定模特：标准 A 字站姿，画布 1024×1536 |
| 2 | `prep_model.py` | 抠出人像；切分头、头发、脸、手、脚的蒙版；生成绿幕版和品红版"生成专用模特"（脖子以下全身都是绿幕，头饰类另有"头发也是绿幕"的版本） |
| 2b | `make_base_strapless.py` | 把展示用底模的圆领肩带修成无肩带款，抹胸、吊带裙上方不会露出连体衣（纯程序处理，因为 AI 接口拒绝这类编辑） |
| 3 | `gen_garment.py` | **每个部件单独穿在绿幕模特身上生成**，然后配准回固定画布（整体对齐加手臂 TPS 校正），再把该槽位区域以外的像素强制贴回原图 |
| 4 | `extract.py` | 把部件抠成透明图层，并做质检（见下文） |
| 5 | `build_manifest.py` | 导出网页用的 WebP 图层、缩略图、叠穿裁剪图和 `manifest.json` |
| - | `batch.py` | 批量生产：生成 → 抠图 → 质检，不合格自动重新生成（默认最多重试 2 次） |

槽位和前后顺序定义在 `slots.json`，从后往前依次是：翅膀（在身体后面）、底模、袜子、鞋、下装、连衣裙、上衣、外层纱裙、袖套、手套、外套、颈饰、头饰。每个槽位都有自己的可编辑区域，并规定能否覆盖手、脚和头发。

单品清单在 `catalog.json`，每件写明 `slot`、描述 `desc`，可选字段：
- `sheer: true`：半透明材质
- `key: "magenta"`：绿色系衣服改用品红色绿幕

## 抠图与质量保证（`extract.py`）

- **不透明部件**：身体区域按"是否还是绿幕色"判断，用色相比例，不受明暗影响；背景区域用 BiRefNet 抠图模型判断。
- **半透明部件**（薄纱、蕾丝、丝袜）：衣服下面的颜色是已知的（就是我们输入给 AI 的那张绿幕模特图，再乘一个亮度校正系数）。对每个像素求解"观测色 = 透明度 × 布料色 + (1 − 透明度) × 底色"，在可行解里选让布料色最不饱和的那个，得到真实的透明度和布料原色。
- **不漏底模**：
  - 衣服边缘和身体轮廓之间宽度小于 21 像素的露缝，用最近的衣服像素颜色补满。
  - 每个槽位有必须覆盖区域，覆盖率需 ≥ 97%。
  - 部件被槽位边界截断的会被标记。
  - AI 把身体画宽或画窄造成的边缘偏差有专门处理。
- **边缘没有锯齿**：所有硬裁剪都改成柔和过渡，透明度再以原图为引导做导向滤波；去除绿幕或品红的溢色；暗色薄纱去偏色。
- 质检结果写在 `assets/raw/<id>_qa.json`。只有 `pass: true` 的部件会进入网页。

## 已知限制

- **生成接口的安全审核**：
  - 丝袜类部件会被 `gpt-image-1.5` 拒绝，脚本会自动改用 `gpt-image-2`。
  - 任何"让底模少穿一点"的编辑都会被拒绝。
  - 暴露程度较高的品类可能需要换成审核更宽松的生成服务。
- **手持道具**（权杖、玩偶）需要不同的手部姿势，暂不支持。
- 只有一个固定姿势。
