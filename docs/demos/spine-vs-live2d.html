2D 角色动画 · 交互演示

SpinevsLive2D

两者都让 2D 角色“动起来”，但思路不同。Spine 用骨骼带动一块块部件，像提线木偶；Live2D 用参数去扭曲一整张原画，像在插画上做立体感。下面两个实验台用同一套交互把差别摆出来。

SPINE · 骨骼动画

骨骼层级 → 部件跟着骨头走

每根骨头只存“相对父骨头”的旋转。转动大臂，小臂和手会一起动。

看点：切换动画时开着“动画混合”，姿势会平滑过渡，关掉则瞬间跳变。“换装”只替换贴在骨骼上的图片，动画数据完全复用。

LIVE2D · 参数变形

参数 → 网格变形 → 一张画“转过头”

原画被切成图层并铺上网格，参数值决定网格怎样扭曲。没有骨头，只有一组可调的数值。

看点：把指针移到头像上，或关掉“跟随”后拖 AngleX。脸没有旋转，是网格被挤压：近处的五官和刘海移得多，远处的后发反向移动，头发尖还带物理惯性。

怎么选

选 SPINE

角色要“全身动”

  • 横版/战斗/场景游戏，动作种类多
  • 同屏角色多，或要跑在低端设备上
  • 需要换装、部件复用
选 LIVE2D

角色要“对着你说话”

  • 聊天、陪伴、直播这类近景半身场景
  • 需要眼神跟随、口型同步、细腻表情
  • 美术以一张精美立绘为核心
对 BONDHOP 而言

陪伴形象优先 Live2D

  • 聊天界面里角色是半身近景，表情和口型最重要
  • TTS 音量可直接写 ParamMouthOpenY，情绪标签映射到 expression
  • 若以后要全身小人或场景互动，再引入 Spine 做 Q 版形象
