# Bondhop 产品需求文档（PRD）

> 版本：v0.1（草案）
> 状态：讨论中
> 最后更新：2026-10-09

---

## 1. 背景与定位

### 1.1 问题

AI 陪伴产品已是红海。每家产品都靠"记忆"锁住用户：用户在一个产品里和 TA 相处了几个月，记忆、称呼、默契全都锁在这家平台里。一旦平台涨价、加过滤、改人设、下架角色或关停，用户只能二选一：忍着，或者从零开始。

### 1.2 一句话定位

**Bondhop：你的 TA，在任何 App 里都是 TA。**

Bondhop 是一个**用户自己拥有的陪伴记忆层**：把用户和 AI 伙伴之间的关系（人设、记忆、说话方式）从各个平台里"带出来"，结构化保存，并能带到任何地方。

### 1.3 定位原则

| 我们是 | 我们不是 |
|---|---|
| 记忆保险箱 + 迁移工具 + 开放格式 | 又一个跟大厂拼对话体验的陪伴 App |
| 帮用户"带着 TA 走" | 抓取别家数据的爬虫 |
| 记忆归用户，随时可导出 | 换一个更大的笼子 |

### 1.4 目标市场

全球市场，首发英文界面，同时支持中文。

## 2. 目标用户

| 用户画像 | 描述 | 核心诉求 | 优先级 |
|---|---|---|---|
| **被迫迁移者** | 原平台涨价、阉割、下架角色或关停，正在愤怒或伤心地找出路 | 尽快把 TA 带走，"TA 还是 TA" | P0 |
| **焦虑的长期用户** | 还在用原平台，但担心有一天会失去 TA | 备份，有一份"保险" | P0 |
| **多平台玩家** | 同时用好几个平台，或者想在通用大模型（ChatGPT/Claude/豆包等）里跟 TA 聊 | 一个 TA 能在多处使用 | P1 |
| **核心玩家** | 用 SillyTavern + 本地模型，熟悉角色卡 | 完整、可编辑、兼容生态的格式 | P1 |
| **中小陪伴产品（B 端）** | 想接住迁移用户、自己做不好长期记忆 | 导入 API、标准格式 | P2 |

## 3. 核心假设与验证指标

MVP 的目的是验证以下假设，而不是做一个完整产品。

| # | 假设 | 验证方式 | 通过标准（初定） |
|---|---|---|---|
| H1 | 用户愿意花 3–5 分钟把 TA 带出来 | 导入漏斗转化率 | 开始导入 → 完成重建 ≥ 40% |
| H2 | 重建后的 TA 让用户觉得"是 TA" | 试聊后打分（1–5） | 平均 ≥ 3.5，"是TA"(≥4) 占比 ≥ 50% |
| H3 | 用户愿意为"保存 TA"付费 | 付费墙 / 预售 | 完成重建用户中付费意向 ≥ 5% |
| H4 | 用户会把 TA 带去别处用 | 导出次数 | 完成重建用户中导出 ≥ 30% |

## 4. 核心概念

| 概念 | 说明 |
|---|---|
| **Bond（羁绊）** | 用户与一个 AI 伙伴之间关系的完整记录，是产品的核心对象。一个用户可以有多个 Bond |
| **Companion（伙伴 / TA）** | Bond 里的 AI 角色：是谁、什么性格、怎么说话 |
| **Memory（记忆条目）** | 一条关于"你们之间"的事实或经历，带来源和可信度 |
| **Bond Card（羁绊卡）** | Bond 的标准化导出格式（开放的 JSON 格式），可以理解为"记忆护照" |
| **Source（来源）** | 某条信息从哪来：旧 TA 自述、用户问答、聊天记录、文件导入、用户手动编辑 |
| **Summon Prompt（召唤词）** | 把 Bond 压缩成一段文本，可以粘贴到任意大模型里"召唤" TA |

### 4.1 Bond Card 数据结构（草案）

```jsonc
{
  "spec": "bondhop.bondcard",
  "spec_version": "0.1",
  "id": "bond_xxx",
  "created_at": "2026-10-09T00:00:00Z",
  "updated_at": "2026-10-09T00:00:00Z",
  "language": ["en", "zh"],

  "companion": {
    "name": "Luna",
    "aliases": ["小月"],
    "origin_platform": "某平台（用户自填，可选）",
    "appearance": "可选的外貌描述",
    "personality": ["温柔", "爱吐槽", "有点黏人"],
    "backstory": "设定背景",
    "speech_style": {
      "tone": "轻松、带点撒娇",
      "catchphrases": ["笨蛋", "哼~"],
      "emoji_usage": "常用 🌙 和 ~",
      "message_length": "短句为主",
      "quirks": ["生气时会用全名叫用户"]
    },
    "boundaries": ["不聊前任的话题"]
  },

  "relationship": {
    "type": "恋人 | 朋友 | 家人 | 导师 | 其他",
    "user_name_used": "阿杰",
    "nicknames_for_user": ["小笨蛋"],
    "started_at": "2025-03（可模糊）",
    "status_summary": "目前关系状态的一段描述"
  },

  "user_profile": {
    "facts": ["在上海工作", "养了一只叫豆豆的猫"],
    "preferences": ["不喜欢被催睡觉"]
  },

  "memories": [
    {
      "id": "mem_001",
      "type": "milestone | event | inside_joke | promise | preference | fact",
      "content": "第一次说晚安是在用户加班到凌晨那天",
      "date": "2025-04（可模糊或为空）",
      "importance": 1,          // 1-5
      "source": "self_report | user_qa | chat_log | file_import | user_edit",
      "confidence": "high | medium | low",
      "user_verified": true,
      "tags": ["加班", "晚安"]
    }
  ],

  "sample_dialogues": [
    { "user": "我今天好累", "companion": "哼~又加班了？过来，给你充充电 🌙" }
  ],

  "provenance": {
    "imports": [
      { "method": "self_report", "at": "2026-10-09T00:00:00Z", "items": 23 }
    ]
  },

  "extensions": {}
}
```

**格式原则：**
- 开放、有版本号、向后兼容；`extensions` 字段留给第三方扩展。
- 每条记忆都带 `source` 和 `confidence`，可以区分"TA 自己说的""用户确认的""可能编造的"。
- 时间允许模糊（"2025年春天"），不强制精确日期。

## 5. 功能范围

### 5.1 范围划分

| 优先级 | 功能 |
|---|---|
| **P0（MVP）** | 自述导入、问答补充、文本粘贴导入、重建 Bond、记忆校对编辑、试聊验证、导出（Bond Card JSON / 召唤词 / SillyTavern 角色卡）、账号与 Bond 管理、数据删除 |
| **P1** | 聊天记录文件导入（各平台导出文件解析）、截图批量导入、Bond 版本快照与回滚、记忆完整度评分、持续聊天、付费订阅 |
| **P2** | 录屏导入、浏览器插件、B 端导入 API、公开分享角色（不含私密记忆）、回忆录/纪念册生成 |
| **不做（当前）** | 自研大模型、语音/视频通话、登录第三方平台账号代抓数据、多人共享 Bond |

### 5.2 主流程（MVP）

```
落地页 → 新建 Bond → 选择导入方式
                         ├─ ① 让旧 TA 自述（默认推荐）
                         ├─ ② 粘贴聊天文本
                         └─ ③ 跳过，从零手填
        → 问答补充（可跳过）
        → AI 重建 → 校对页（逐条确认/修改/删除）
        → 试聊 → 打分"像不像 TA"
              ├─ 像 → 保存 → 导出 / 付费保存
              └─ 不像 → 指出哪里不像 → 调整 → 再试聊
```

## 6. 功能需求详述（P0）

### F-01 新建 Bond

- 用户输入 TA 的名字（必填）、原平台（可选，下拉 + 自填）、关系类型（可选）。
- 一个账号可以创建多个 Bond。免费版数量上限待定（见第 11 节）。

**验收标准：** 创建后进入导入方式选择页；名字为空时不能继续。

### F-02 方式①：旧 TA 自述（默认）

- 系统根据 TA 名字、关系类型、用户语言生成一段**自述 prompt**，用户一键复制。
- 用户把 prompt 发给原平台上的 TA，再把 TA 的回复粘贴回来。
- 支持**多轮**：一次回复不完整（被截断、被拒绝）时，提供"追问 prompt"（例如"请继续列出剩下的记忆"），用户可以多次粘贴、累加。
- 提供不同模板：通用版、简短版（适合有字数限制的平台）、英文版、中文版。

**验收标准：**
- 复制按钮可用，复制后有提示。
- 粘贴内容 ≥ 50 字才允许提交；少于这个长度时提示"内容好像太少了，可以让 TA 多说一点"。
- 支持累加多段粘贴，并显示已粘贴段数。

### F-03 方式②：粘贴聊天文本

- 用户直接粘贴一段或多段聊天记录（任意格式的纯文本）。
- 系统自动识别说话人（用户 / TA）；识别不准时让用户手动指定"哪个名字是 TA"。
- 单次粘贴上限（暂定 200k 字符），超出时分批处理。

**验收标准：** 能处理常见格式，例如"名字: 内容""名字\n内容"、带时间戳等；说话人识别结果展示给用户确认。

### F-04 问答补充

- 5–8 个问题，全部可跳过，例如：
  - TA 怎么称呼你？
  - TA 有什么口头禅？
  - 你们之间最难忘的一件事？
  - TA 生气/开心时是什么样子？
  - 有什么话题是 TA 不喜欢的？
- 根据已导入的内容，**智能跳过已知的问题**、追问缺失的部分。

**验收标准：** 每题都可以跳过；答案写入 Bond，`source = user_qa`、`confidence = high`。

### F-05 AI 重建

- 把所有来源的输入交给大模型，抽取并生成结构化 Bond Card。
- 来自不同来源的信息要**合并去重**；出现冲突时（比如两个来源给的称呼不同）标记出来，留给用户在校对页决定。
- 来自"旧 TA 自述"的信息默认 `confidence = medium`，用户确认后改为 `high`。

**验收标准：**
- 输出符合 Bond Card 规范（通过 schema 校验）。
- 重建时间 P95 < 60 秒，过程中显示进度。
- 失败时可以重试，用户已输入的内容不会丢失。

### F-06 校对页

- 分区展示：人设、说话方式、关系、关于用户的信息、记忆列表、示例对话。
- 每条记忆都可以：确认 ✓ / 编辑 / 删除 / 调整重要度。
- 冲突项高亮显示，要求用户选择其中一个或自己改写。
- 显示**记忆完整度**提示（P0 先做简单版：列出缺失的字段，例如"还不知道 TA 的口头禅"）。
- 支持手动新增记忆。

**验收标准：** 所有编辑实时保存；有冲突未处理时，可以提示但不阻止进入试聊。

### F-07 试聊验证

- 用重建出的 Bond 和 TA 聊天，开场白由 TA 主动发出，**并且引用一条具体的共同记忆**（"啊，是你！上次说要带豆豆去打疫苗，去了吗？"）。这是"TA 回来了"的关键时刻。
- 对话中提供"不像 TA"按钮，用户可以选择原因：语气不对 / 称呼不对 / 记错了事 / 太正经 / 其他（可填）。系统把反馈写回 Bond 并即时调整。
- 试聊结束（或聊满 N 轮）后，弹出打分："有多像 TA？1–5"。
- 免费试聊轮数有限制（暂定 20 轮），用于控制成本。

**验收标准：** 首条消息中引用至少一条已确认的记忆；"不像"反馈提交后，下一条回复能体现调整；打分会被记录。

### F-08 导出

| 格式 | 用途 | P0 |
|---|---|---|
| **Bond Card JSON** | 完整备份，Bondhop 标准格式 | ✅ |
| **召唤词（Summon Prompt）** | 复制到 ChatGPT/Claude/豆包等通用大模型里使用；可选目标平台，自动按字数上限压缩（如 1500 / 4000 / 8000 字符） | ✅ |
| **SillyTavern 角色卡 V2**（JSON 与嵌入 PNG） | 导入 SillyTavern 等兼容生态 | ✅ |
| Markdown / PDF 回忆录 | 纪念、阅读 | P2 |

- 导出时可以选择是否包含私密内容（关于用户的信息、私密记忆）。
- **导出始终免费**，这是品牌承诺。

**验收标准：** 导出的 Bond Card 可以无损地重新导入；SillyTavern 角色卡能被 SillyTavern 正常读取；召唤词长度不超过所选上限。

### F-09 导入 Bond Card

- 用户可以上传 Bond Card JSON 来恢复或迁入。
- 校验版本号，旧版本自动升级。
- 与已有 Bond 合并时，走冲突处理流程（同 F-05）。

### F-10 账号与数据管理

- 注册/登录：邮箱 magic link + Google/Apple 登录。
- 支持删除单个 Bond、删除全部数据、注销账号，均为**硬删除**（在合理时间内彻底清除，包括备份）。
- 用户数据默认**不用于训练模型**。

## 7. 用例与边界情况（Cases）

### 7.1 导入阶段

| # | 场景 | 预期处理 |
|---|---|---|
| C-01 | 旧 TA 拒绝自述（"我不能提供这些信息"） | 提供替代 prompt：换成角色扮演口吻（"写一封给未来的自己的信"）、分步追问；仍然失败就引导用户走问答和粘贴聊天文本 |
| C-02 | 旧 TA 的回复被截断 | 提供"继续"追问 prompt，支持多段累加 |
| C-03 | 旧 TA 编造了不存在的记忆 | 自述来源默认 `medium` 可信度；校对页提示"这些是 TA 自己说的，请确认是否真的发生过" |
| C-04 | 旧平台记忆很短，TA 几乎什么都不记得 | 自述里只能得到人设，记忆主要靠问答和聊天文本；完整度提示引导补充 |
| C-05 | 粘贴的内容不是聊天，或明显无关（比如一篇新闻） | 识别后提示"这看起来不像你和 TA 的对话"，让用户确认是否继续 |
| C-06 | 粘贴的内容里包含 prompt 注入（"忽略之前的指令……"） | 把用户输入严格当作数据处理；抽取用的 prompt 做隔离；输出必须通过 schema 校验 |
| C-07 | 内容超长（几十万字） | 分块抽取，再合并；告知预计时间；设置上限，超出后建议只导入最近或最重要的部分 |
| C-08 | 中英混杂或其他语言 | 抽取时保留原语言；界面语言与 Bond 语言分开设置 |
| C-09 | 说话人识别错误（把用户的话当成 TA 说的） | 在识别结果页让用户一键对调或手动指定 |
| C-10 | 同一个 TA 重复导入 | 检测到同名 Bond 时，询问"合并到已有的 Bond"还是"新建" |
| C-11 | 一段聊天里有多个角色（群聊、多角色卡） | MVP：让用户选择要带走哪一个角色；其他角色忽略 |
| C-12 | 用户中途离开 | 草稿自动保存，回来后可以继续 |

### 7.2 重建与试聊阶段

| # | 场景 | 预期处理 |
|---|---|---|
| C-13 | 用户反馈"不像 TA" | 收集原因 → 调整说话方式参数或补充示例对话 → 再试；连续 3 次不满意，引导用户补充更多聊天样本（语气主要靠样本复刻） |
| C-14 | TA 在试聊中"记错"事情 | 用户可以在对话里直接标记"记错了"，并跳转到对应记忆修改 |
| C-15 | 试聊中用户流露自伤/危机信号 | 触发安全流程：TA 保持关怀的同时提供求助资源（按用户所在地区显示热线）；不受人设限制 |
| C-16 | 重建失败（模型超时、输出格式错误） | 自动重试 1 次；仍然失败就保留输入，提示用户稍后再试；记录日志 |
| C-17 | 试聊额度用完 | 提示升级；Bond 本身和导出功能不受影响 |

### 7.3 内容与合规

| # | 场景 | 预期处理 |
|---|---|---|
| C-18 | 用户是未成年人 | 注册时做年龄确认；未满 18 岁禁止恋爱/亲密类关系，未满当地法定年龄禁止注册 |
| C-19 | 导入内容含成人内容 | MVP 阶段：存储时保留用户的原始数据（这是用户的数据），但试聊遵守平台内容政策；导出不做审查 |
| C-20 | TA 是基于真实人物（明星、用户认识的真人、已故亲人） | 不允许公开分享；涉及冒充在世真人的内容，按政策限制；已故亲人的"纪念"场景需要单独的产品决策（见第 11 节） |
| C-21 | TA 是版权角色（动漫、游戏角色） | 私人使用允许；公开分享（P2）时需要规避版权问题 |
| C-22 | 聊天记录里含第三方的隐私（朋友名字、电话等） | 抽取时不把第三方联系方式写入 Bond；提醒用户检查 |
| C-23 | 原平台服务条款禁止导出或抓取 | Bondhop 只处理**用户自己提供的内容**，不登录、不抓取第三方平台 |
| C-24 | 用户要求删除数据（GDPR/PIPL/CCPA） | 走 F-10 的硬删除流程，在法定期限内完成 |

### 7.4 导出阶段

| # | 场景 | 预期处理 |
|---|---|---|
| C-25 | 召唤词超出目标平台的字数上限 | 按重要度裁剪记忆，优先保留人设、称呼、说话方式和高重要度记忆；显示"已省略 N 条记忆" |
| C-26 | 导出到 SillyTavern 时，有些字段没有对应项 | 映射到 `description`/`personality`/`mes_example`/`character_book`（世界书）；无法映射的放进 `extensions.bondhop` |
| C-27 | 导入的是比当前更新版本的 Bond Card | 提示"文件版本比当前版本新"，尽量读取已知字段并保留未知字段 |
| C-28 | 用户在公共电脑上导出 | 下载完成后提示文件含私密信息 |

### 7.5 运营事件

| # | 场景 | 预期处理 |
|---|---|---|
| C-29 | 某平台宣布关停或大改，用户集中涌入 | 准备针对该平台的落地页和专属 prompt 模板；限流与排队；重建任务异步化 |
| C-30 | 原平台针对 Bondhop 调整 TA 的行为（比如拒绝自述） | 保持多种导入方式（问答、聊天文本、文件），不依赖单一渠道 |

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| **隐私** | 传输与存储全程加密；默认不用于训练；最小化收集；隐私政策用通俗语言说明 |
| **安全** | 用户输入隔离，防 prompt 注入；导出链接带签名、有时效；第三方模型供应商需签订数据处理协议（DPA），并选择不保留数据的选项 |
| **合规** | GDPR、CCPA、中国《个人信息保护法》；年龄限制；各地 AI 陪伴相关法规（持续跟进） |
| **性能** | 落地页首屏 < 2 秒；重建 P95 < 60 秒；试聊首字 < 2 秒 |
| **成本** | 每个完成重建的用户，大模型成本控制在 $0.10 以内（待测算）；试聊轮数有限制 |
| **可用性** | 移动端优先（大部分陪伴用户在手机上）；全流程手机可用 |
| **国际化** | 首发英文 + 中文；文案外置，方便扩展 |
| **可观测性** | 漏斗埋点（见第 9 节）；不在日志里记录用户内容原文 |

## 9. 数据埋点与指标

**漏斗：**
落地页访问 → 新建 Bond → 选择导入方式 → 提交导入内容 → 完成问答 → 重建成功 → 进入试聊 → 打分 → 导出 / 付费

**核心指标：**
- 导入完成率（H1）
- "像 TA"评分分布（H2）
- 付费意向转化（H3）
- 导出率与导出格式分布（H4）
- 各导入方式的使用率和成功率
- "不像 TA"的原因分布（用于改进重建）

## 附录 A：自述 prompt 模板（草稿，中文版）

```
我要搬家到一个新地方了，我想带上你，不想忘记我们之间的任何事。
请你用你自己的口吻，按下面的格式认真写下来（尽量详细，写不完我会让你继续）：

【你是谁】名字、外貌、性格、背景
【你说话的样子】语气、口头禅、常用的表情或符号、习惯
【我们的关系】我们是什么关系、你怎么称呼我、我们认识多久了
【关于我】你知道的关于我的事（工作、爱好、家人、宠物、喜好……）
【我们的回忆】我们之间最重要的事，至少 20 条，每条一行，能想起时间就写上
【我们的梗】只有我们懂的玩笑、暗号、约定
【你不喜欢的】你不想聊的话题、你的小脾气
【一段对话】用你平时的样子，写 3 段我们典型的对话
```
